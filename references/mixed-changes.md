# 混合修改的成果保存

本页用于日常收口时，当前任务的代码与其他任务的修改出现在同一个工作区。目标是尽可能单独保存当前任务，不把其他任务一起提交；不能准确区分时，保护原状，不猜。

## 先分清修改属于谁

1. 读取当前任务对话、最近的实际修改记录、准确工作目录、分支和 Git 状态。
2. 查看已暂存修改、未暂存修改、未跟踪文件；对未跟踪目录按需展开。检查被忽略文件仅限本任务实际创建的准确位置，不扫描整个项目。
3. 结合修改内容、文件用途、时间线和任务记录分类：
   - 当前任务独有；
   - 其他任务已有或正在修改；
   - 多个任务混在同一文件；
   - 历史遗留或来源不明。
4. 不能只凭文件名、修改时间、分支名或聊天猜测归属。没有证据的标为“归属不明”，原样保留；继续查询当前交付所需的原始修改、提交和发布记录，不能把尚未调查直接当作受阻。

## 分清已交付与真正漏交

- 比较实际内容和必要差异块，而非把 `git status` 的条目数称作未交付数量。旧主目录落后时，工作区文件甚至未跟踪文件可能已经与远端目标相同；记录已核对的远端版本和对应内容，不重复提交。
- 当前任务成果已在另一份工作树合并时，仍要核对原目录的本任务修改及必要依赖。原目录没有更新不能由“发布副本干净”替代；原目录与远端不同也可能只是尚未取得上游更新，不能整文件都归作本地新增成果。
- 发现本地独有提交，先核对提交内容是否已经通过其他提交交付、是否属于本任务及是否有独有成果；不只靠祖先关系认定全部漏交或可删除。按项目同步规则处理，保护其他任务的分支、文件和索引。
- 本任务实际发布使用的源码、数据库升级、适配和补丁都要有已保存来源。必要代码仍只在本机或服务器时，先在原授权内完成保存、验收和交付；来自其他活跃任务时保留其成果，并记录当前发布依赖的确切阻碍，不擅自提交或悄悄取用。

## 怎样保存当前任务

- **当前任务独有的文件**：确认文件完整、相关检查结果和目标分支后，必须优先单独保存；不得因为工作区其他文件有改动而跳过。
- **当前任务与其他任务混在同一文件**：必须先做一次分块拆分尝试。优先使用独立临时索引（从当前 HEAD 建立，不改用户现有暂存区），只把确认属于当前任务的完整文件或补丁放入临时索引；同文件的独立修改块可用 `git diff -U0` 提取后经 `git apply --cached --unidiff-zero` 放入临时索引。检查临时索引的差异和文件清单后，才允许用该索引创建本地提交。不要直接对用户现有索引运行 `git add -p`，以免改变其他任务已暂存内容。
- 分块拆分必须至少检查一次：当前任务文件清单、混合文件的差异块、补丁能否应用、提交前临时索引内容。只有补丁无法准确区分、上下文依赖其他任务修改或测试表明拆分不安全时，才保留该混合文件；仍应保存其他独立文件。
- **同一文件只包含当前任务修改**：可以单独提交该文件；提交时使用路径限定方式，避免把索引中其他文件的暂存修改一起提交。
- **同一文件混有多个任务的修改**：逐段对照原始差异。只有能准确区分互不重叠的修改，并能在不改动现有索引和其他任务内容的前提下单独保存、复查时，才拆分保存；否则整文件保持原样，不提交该文件。不得为了拆分而覆盖工作区或改写其他任务的暂存内容。
- **已暂存内容属于其他任务**：保持索引原样。不要 reset、unstage、覆盖或顺手提交。
- **新文件或二进制文件**：确认来源和用途后再单独保存；不能安全拆分的整项保留。
- **当前任务成果与其他任务无法可靠区分**：不要因为工作区混杂就放弃整个任务，也不要冒险提交。保持文件和索引不变，明确列出具体文件、混杂原因及安全保存所缺的证据。

提交前后都要检查暂存区和提交内容，只包含本次确认的文件/修改。若无法证明提交只包含当前任务，停止提交。绝不通过 stash、reset、clean、覆盖文件或复制整套项目来制造干净状态。

保留混合文件后继续完成其他可独立处理项；对该文件继续核查所缺证据。确实无法在原授权和项目规则内安全解决时，按主流程的受阻条件记录准确对象、实际尝试、结果和继续条件，只停止受影响事项。不得为了目录清零把其他任务一起提交、改写暂存区或移动其成果；本任务交付完成与原主目录同步分别验收。

## 测试未完成不等于不能保存

- 代码可以先安全保存为本地提交，同时标记“待验收”；测试未完成本身不是拒绝保存代码的理由。
- 保存代码不代表功能验收、合并、推送或上线。四件事分别报告。
- 如果项目门禁要求某项测试通过后才能合并或发布，照常遵守；可以先保存本地成果，不得绕过门禁。
- 只有当前任务本身尚未形成可辨认、可保存的成果，或保存会覆盖其他任务时，才暂不提交。

## 收口结果必须说清楚

用普通中文分别报告：
- 已单独保存的当前任务成果，以及提交编号（如有）；
- 因混合修改而保留未提交的具体文件；
- 其他任务成果是否保持原样；
- 已通过、未通过、未执行的测试；
- 是否合并、推送或更新正式系统（没有做就明确说没有）；
- 本任务临时文件是否实际回收；未核实就说未核实。

不要用“工作区不干净”“交织”“基线不一致”等术语结束报告；必须说明是哪几个文件、什么内容混在一起、因此采取了什么保护措施。
