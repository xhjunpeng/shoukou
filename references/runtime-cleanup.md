# 运行资料分类与复查

用于本次任务的完整收口、阶段交付和已授权历史清理。检查脚本只读；清理权限来自用户已确认的范围，分类和占用证明来自真实任务记录。保留聊天、目录或预览，只保留继续使用它们所需的内容，不自动保留所有历史验收批次。

项目级调用先按 [默认范围与保护边界](default-behavior.md) 区分已结束、继续开发、日常环境及待确认对象。下文的“本任务”指本次已纳入处置范围的具体任务；全仓引用审计不扩大为修改其他任务数据。日常服务所依赖的启动源码、冻结依赖、配置、凭据和配对同样属于必须保护的运行材料，不因位于 `.runtime` 或工作树而成为可重建测试缓存。

## 分类和处置

| 分类 | 判断依据与去向 |
| --- | --- |
| `cache` 可重建缓存 | 明确由本任务生成，有可执行的重建方法，且不再被服务、构建或其他任务使用；完整收口时清理。依赖可按锁文件恢复，但共享依赖仓库不在单个任务清理范围。 |
| `test-data` 隔离测试数据 | 已确认属于本任务的隔离数据库、临时上传件和验收环境，能由迁移及测试材料恢复，确认不含唯一原件或真实业务数据后清理。不能将整个 `.runtime` 或 `.gaga` 一概归入此类。 |
| `evidence` 验收材料 | 必要部分保留能对应准确最终候选的报告、日志和截图；已被替代的中间材料核对覆盖关系后按 `superseded` 清理。必要原件删除前逐文件外置并核对摘要，不默认保留或备份全部历史批次。 |
| `business-data` 持久业务材料 | 本地业务数据库、导入原件、用户成果和凭据按已确认用途保留，不凭 Git 忽略状态删除。 |
| `unknown` 用途待核实 | 保留准确对象，记录缺口和下一项核实动作；结果为部分完成，不阻塞其他已可安全处理的对象。 |

回收可重建数据前，逐组列明准确路径、所属任务、类别、重建依据、使用者查询及处置结果。使用已有退出入口结束一次性验收服务，再处理不再使用的数据。需要保留的预览、原有服务和业务数据库单独列明。停服务与删除数据库是两件事；脚本不会替代理解项目的连接关系或自动停止程序。

阶段交付继续开发时可以保留仍需使用的临时环境，写明复核事件，例如“本任务最终验收结束”。完整收口保留缓存或测试数据时，必须有明确约定及复核事件；信息不足使用 `blocked`。不采用仅按天数、目录名、PID 文件或端口判断的自动删除，不把未知对象改标为 `agreed`。

## 操作前证据

使用完整 `inspect-repo.sh --json` 输出，保存到所有待复查目录之外，计算该文件 SHA-256。完整盘点包含仓库公共 Git 目录、观察时间、逐工作树忽略文件清单、占用和所在磁盘可用空间。摘要省略完整清单，不能作为此证据。盘点所有目录不授权清理其他任务；最终只核对台账中的主目录和任务目录。

已有源码、暂存或未跟踪成果按原收口规则处理。下面的运行资料核对覆盖 Git 忽略的数据，不能替代源码交付检查。非忽略临时产物先确认归属并按正常文件处理，不能为了通过检查扩大忽略规则。

完整空间另按 [全目录空间与历史材料收口](storage-cleanup.md) 采集和复查，覆盖非忽略文件、嵌套副本、旧备份与本轮外置材料。本页的 ignored_usage 仅是子集；不能据此宣布完整目录已经精简。

## 最终台账

在最终复查台账中加入下列 `runtime`，使用 `schema_version: 2`。主目录与 `directories` 中的每个目录都必须在 `classifications` 出现，没有忽略文件时填 `{}`。路径必须绝对、互不嵌套；每个根目录仅指本次台账的对象。

```json
{
  "runtime": {
    "before_inventory": "/absolute/outside-all-roots/before.json",
    "before_sha256": "完整盘点文件的SHA256",
    "classifications": {
      "/absolute/main-checkout": {},
      "/absolute/task-worktree": {
        "node_modules/": {
          "kind": "cache", "action": "removed",
          "reason": "本任务结束，依赖不再使用",
          "source": "任务记录及本次使用者查询记录位置",
          "rebuild": "按本项目锁文件恢复依赖"
        },
        ".gaga/acceptance/": {
          "kind": "test-data", "action": "retained", "retention": "blocked",
          "reason": "尚未确认哪些批次仍被预览引用",
          "source": "本次预览查询记录位置",
          "review": "核实预览实际引用的数据批次后处理"
        },
        ".runtime/report.log": {
          "kind": "evidence", "action": "archived",
          "reason": "保留本次最终验收日志",
          "source": "验收及外置副本核验记录位置",
          "backup": "/absolute/outside-all-roots/report.log",
          "sha256": "外置前核对原件与副本得到的SHA256"
        }
      }
    },
    "services": {
      "source": "本次真实服务及进程查询原始记录位置",
      "complete": true,
      "observed_at_unix": 0,
      "items": [
        {
          "name": "本任务一次性验收数据库", "outcome": "stopped", "pid": 12345,
          "reason": "使用项目已有退出入口正常结束",
          "source": "该服务身份、退出结果及进程复查记录位置"
        }
      ]
    }
  }
}
```

规则必须恰好覆盖操作前与操作后的全部忽略文件，每个文件仅匹配一个准确文件名或以 `/` 结束的目录前缀。遗漏、新生成的未分类数据、重叠和无匹配规则均拒绝。大组内有不同去向时拆成互不重叠的批次或准确文件，不能用宽目录规则覆盖必要资料。

- `removed`：仅用于已确认可重建的 `cache` 和 `test-data`，必须填 `rebuild`；复查文件、目录或符号链接是否仍在。规则不执行删除。
- `retained`：填 `reason`、`source` 和 `retention`。`agreed` 来自明确约定；`required` 仅用于必要证据、持久业务材料或原有服务；`blocked` 表示尚未完成。缓存、测试数据、未知数据和保留服务还须填 `review`。未知数据始终属于待核实项。测试数据及必要材料的原有文件须仍为普通文件，丢失、替换成链接或目录会拒绝；必要证据和业务材料的类型、大小或修改时间变化时列为待复核，不靠重新采集盘点掩盖资料丢失。
- `archived`：只接受准确文件、所有复查根目录之外的普通副本及 SHA-256；检查原路径已不在、外置文件存在且摘要一致。目录归档须逐文件列明。外置摘要来自删除前原件与副本核验，不是凭空填入的证明。
- `superseded`：仅用于已被替代的 `evidence`，填 `replacement`（保留下来的普通文件绝对路径）、`sha256` 和 `coverage`（准确版本、结论及必要原始证据的覆盖依据）。原文件/批次必须实际不在，替代材料摘要须一致；目录规则可分组。唯一原件、业务材料和仍有必要的证据不能用此方式删除。替代材料及其他外置内容还须纳入全目录空间核对，不以转存代替释放。

服务没有启动时，完成真实查询后可填 `items: []`；查询不足填 `complete: false`，不得因列表为空推定无人使用。查询记录须在最近 120 秒内。每个服务的 `outcome` 为 `stopped`、`retained` 或 `unknown`；停止项须记录原 PID，脚本用信号 0 检查进程是否仍存在，不发送终止信号。PID 被复用也会保守拒绝，需重新核实，不能直接停止新进程。保留项填约定或必要性、来源和复核事件；未知项为部分完成。

必须保留的在线服务正常更新时，使用 [在线保留文件的变化](storage-cleanup.md#在线保留文件的变化) 中的准确单文件 `dynamic` 声明。ignored 分类新增 `kind: runtime` 仅接受该声明核实通过的 `.log` 追加文件；无声明、宽目录声明或声明无效均拒绝。JSON 缓存仍使用 `kind: cache`，另填 `rebuild`、符合现有约定的 `retention: agreed` 和 `review`；不能以填 agreed 制造保留授权。其他必要材料继续原有严格保护，不能改标为 runtime/cache。核验期间 HEAD、分支、正常 Git 改动、嵌套仓库及其他忽略资料的变化仍拒绝；精确动态观察不要求停服，也不证明内容保全。

## 结果与边界

最终复查分别给出代码引用结果和 `runtime` 结果。没有 `runtime` 的旧版台账仍能核对 Git，但整体为 `partial`，不能沿用旧版 `complete` 宣称完整收口。声明与文件或进程现状矛盾为 `blocked`；信息不足或有待处理对象为 `partial`。

占用采用忽略文件的逻辑大小和分配块统计，不读取数据库内容，不跟随符号链接，并在单个根目录内去重硬链接。它不覆盖目录元数据、Git 历史和全局共享缓存；跨根目录的硬链接、压缩和共享块会影响物理占用估算。

报告三组数：目标忽略数据前后占用及差值、外置资料量、各磁盘可用空间变化。备份、迁移或回收站仍可能占用同一磁盘；其他程序也会改变可用空间，不能将目录差值直接当作本任务实际释放量，无法归因时明确写“未能单独确认实际释放量”。保留的对象逐组写明容量、原因、依据和复核事件。

脚本核对文件现状、摘要、范围和明显矛盾，不认证调用者声明的任务归属、删除授权、服务查询完整性或业务数据分类。同路径留存检查使用清单和文件元数据，不证明逐字节内容一致；需要内容保全时按外置副本路径逐文件验证 SHA-256。真实清理前仍核对原始记录；移除整个工作树继续执行 cleanup-check.md 的应用保护和清理前检查。已批准清理目录内的临时数据不要求移交聊天，也不授权绕过工作树删除保护。
