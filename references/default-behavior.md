# 默认范围与保护边界

仅在明确项目级、整目录或历史清理时读取。本页保留完整保护边界；日常 `$shoukou` 按 SKILL.md 的轻量路径执行，不加载本页、不强制建立台账。全局授权及应用保护不变。

## 解析项目与任务

默认项目来自应用确认的当前聊天目录及其来源仓库。核对 Git 公共目录和项目记录；业务应用涉及其他仓库时另核对真实应用标识，不凭标题、端口或同名目录纳入。项目不明确时先只读定位；多个可能项目仍无法区分，才询问用户项目选择。单独调用不授权跨项目巡查或全盘清理。

默认只在当前任务范围内核对聊天、分支、工作目录、未提交成果及运行资源，先按 [产物台账](artifact-ledger.md) 接收登记；用户明确要求项目级收口时才核对该项目全部候选。近期聊天列表、空闲状态或一次工具返回不足以证明全量占用；保留查询不完整的真实状态。用户只需决定业务任务是否继续，不承担辨认分支、查目录或补齐工具能查询的事实。

| 对象状态 | 判断与处置 |
| --- | --- |
| 已结束 | 最新用户约定和实际任务范围能证明已结束，候选及未提交成果均有去向；执行适用验收及交付后，才进入清理。仅有合并记录不足以认定整项任务结束。 |
| 继续开发 | 用户有明确继续约定，或实际记录证明仍有范围内工作；保护其分支、改动、目录、预览和数据。项目级调用不代替另一个任务执行阶段提交或变更。 |
| 长期保留 | 主线、项目约定的长期引用、日常运行环境和必要资料按真实政策或依赖保留，记录依据。 |
| 待确认 | 任务归属、结束状态、用途或占用无法证实，保留准确对象并报告缺口。关键业务意图确实无法查询时一次询问；不把未知写成用户同意保留或任务已结束。 |

范围限定优先：单独 `$shoukou` 和 `收口当前任务` 均只处理当前任务；`项目收口` 或明确的 `历史清理` 才扩大范围；`继续开发，仅合并本批` 是阶段合并；`盘点所有分支` 是只读。只要求解释、评审或修改本技能时，不执行以上任何项目收口动作。

## 保留聊天与回收目录

默认保留所有聊天历史、不删除、不归档；按真实约定保护需要继续开发的环境。聊天有未归档历史，不等于用户要求每个历史任务的旧数据库、依赖和服务均保持可启动；也不授权手工删除仍有应用关联的目录。

对已结束任务，只为安全回收目录而执行确有必要、受支持的关联处理。无须恢复旧任务环境来证明聊天仍有历史。仍被聊天关联、原生接口拒绝、附件失配或占用不明时，保留该目录并报告受阻，继续处理满足条件的分支和无用临时数据。不能用“只保留历史”绕过 SKILL.md 的应用保护、原生归档和资料保全检查。

## 单窗口统筹与必要协作

明确项目级收口时，发起聊天负责整个项目的候选台账、处置顺序、证据引用、容量口径及最终复查。日常任务不默认进入本节的项目级批量流程。先通过只读接口取得相关任务状态和已有原始结果；不靠向全部历史聊天重复发送 `$shoukou` 来完成项目收口。用户只需在统筹聊天查看进度和统一结果。

### 当前窗口直接执行

先核实当前生效全局规则中的“项目级收口的单窗口限定例外”及本轮实际授权。适用时，统筹聊天可直接对同一 Git 公共目录下已注册、已确认归属且任务已结束的工作树处理分支检出关系和引用；对有明确项目来源、无使用或重启依赖、可重建且无唯一内容的独立临时批次直接清理。分支动作按 [分支检查与原样保留复查](branch-cleanup.md#只清理分支名原样保留目录) 执行，资料去向按 [全目录分类与复查](storage-cleanup.md) 执行。不以跨目录为由省略核查，不以清理目录为前提拖延引用判断。

在统筹聊天运行 `git -C <准确任务目录> …` 属于本例外的有限收尾，不会把该目录变成当前聊天的开发目录，也不改变原聊天位置。只读读取原聊天记录无需唤醒它；原聊天存在或空闲均不证明任务已结束。存在其他源码/Git 写入者、未提交独有成果、暂存或冲突、继续开发或暂停约定时，保留对应对象。运行服务只写日志不自动证明依赖分支名，也不自动证明可解除检出；核对准确使用、启动配置和重启路径后再判断。

全局例外不覆盖跨目录改源码、提交独有成果、功能验证、同步主目录或迁移服务；这些操作按原有目录归属及专项授权处理。工作树删除仍按应用保护，不改关联、不强制删除、不要求为清理重建历史环境。工具只允许原聊天调用的原生回收入口，在无跨聊天授权时记为该目录的真实能力边界，继续其他动作，不能将其扩展成所有分支受阻。项目不明、例外未生效或本轮要求更窄时先只读查明范围，不由技能假定权限。

### 复用证据，按变化补查

- 本轮共用首次原始盘点和台账，各对象只补充必要材料；后续观察另记，不改写“清理前”记录。完整查询不足仍如实记录，不因集中统筹而假定无人使用。
- 复用验收前，确认来源仓库、准确候选版本、未提交文件状态、验证环境及覆盖范围仍适用，并读取可追溯的原始结果；跨目录只能复用已证明相同的部分。只剩一句“测试通过”、版本不符、文件或环境已变化、缺少覆盖时，补做受影响的检查。整合后项目明确要求的验证仍须执行。
- 业务验收与删除安全检查分别判断。已有交付证据不能替代当前分支头、聊天位置、附件、进程、文件指纹、备份的适用核验；真正操作前仍运行规定的新鲜门禁，结束时仍查询真实 Git、数据和服务状态。

### 原授权内持续完成

未读完记录、材料未分类、运行资料台账未填、尚未查依赖，都是待办；按检查输出的 `execution.unfinished` 连续处理，不按清理批次反复结束并索取同一授权。能在本轮查清的事实继续查清；确需用户决定、实际查询失败或权限/应用限制时，保留准确原始结果，按 [真实停点记录](final-check.md#未完成工作与真实阻碍) 逐对象记录，不把自己的“尚未做”当成外部阻碍。

已经明确暂停的任务记录为 `paused`，保全其代码、数据和失败证据；收口不自动授权恢复实现、重试被安全审查中止的动作或修复越界事项。任务已交付后提出的、尚未获准执行的下一步建议，不自动成为继续开发或保留旧分支的依据，仍核实实际引用依赖。一个暂停或受阻对象只阻塞自身及真实依赖，其他待办继续处理。

无法在当前执行条件下做完时，如实报告哪些是待办、哪些是真实阻碍及已完成事项；不伪造停点证据，不把空分类表改成“全部保留”凑通过。保护现状与调查是否完成分别判断，仍为 `continue` 的对象不能宣称已核实处置完毕。

### 仅在另有明确授权时协作

默认由当前窗口直接执行允许的动作，不发消息、不唤醒原聊天，也不将协作作为收口前提。用户另行明确授权跨聊天协作时，统筹聊天先核实准确目标与归属、当前工具为什么不能执行、原聊天具体能完成什么，以及其余已知前置条件是否可满足。仅凭旧聊天存在、近期列表不完整、缺少当前附件或想补齐报告，不足以批量唤醒原聊天。确需由原聊天查询准确附件时，可将这一次查询作为单独动作；若已有明确阻碍且该查询不会推进处置，直接记录阻碍。

已知聊天仍在目标目录、现用服务仍写入或唯一资料尚未保全时，先在统筹聊天确定解除路径和授权边界。让原聊天再跑一轮相同检查不能解除这些条件。移交会触及 Git、聊天状态或运行环境时，按实际接口契约与已验证行为判断，不把接入受管工作树的接口当成切回普通主目录的通用入口，也不为寻找可用入口反复试迁移。

确有必要且用户授权覆盖时，只向准确聊天发送一次最小任务：准确目录/附件、单一查询或原生动作、已有证据位置、必要边界和返回内容。原聊天仅核实本动作所需的新鲜事实；不重新盘点全项目、不重复整体验收、不新增分支或开发、不向其他聊天继续转发。已授权的同一动作复用授权；尚未授权的消息一次列明对象、动作和原因再请求，普通项目收口不默认包含跨聊天发消息。用户明确要求不同协作方式时，按其范围执行。

受委派聊天在自身聊天的最终回复中记录动作是否执行、原始工具结果、准确对象、必要状态变化和剩余阻碍，不另生成报告，不自行发送回执给统筹聊天。统筹聊天只读取得结果并复查实际状态；消息送达或工具受理不等于回收成功。同一对象、相同阻碍且前提未变化时，不重发指令；已归档聊天消息被拒绝时保留并报告，不为重试而自动恢复。

### 核查结束后避免新增占用

区分业务服务、其他开发任务与本轮核查启动的工具进程；后者不能被解释成业务仍要继续开发或用户要求长期保留目录。只对确属本轮、已完成且有受支持退出方式的临时进程正常结束，不停止其他聊天进程。实际占用未解除时仍保留目录；不为通过门禁省略进程或篡改观察。统筹聊天集中报告已完成项及真实缺口，不再要求所有原聊天各收一次口。

## 日常环境优先保护

数据分类前核对日常服务、预览、定时启动和重启入口的实际依赖，包括其工作目录、冻结源码、依赖、配置、凭据、配对、原数据库及必要文件。当前端口未监听或没有进程，不能证明这些重启材料已失去用途。路径属于任务工作树、名字带 test 或位于 `.runtime`，都不能单独判为缓存。

同一目录混有日常材料和测试批次时，按准确批次或文件拆分，保护仍有依赖的内容；不能用宽目录删除、仅留一个数据库文件或“代码已合并”替代完整启动依赖保全。涉及其他任务或项目的共用资源只记录保护，不随本任务清理。

只结束准确归属本任务、已不再需要的一次性验收服务，使用项目已有退出入口。Git 主线同步不等于部署，不授权对日常库执行新迁移、重建空库、重新配对、升级应用或迁移服务。

## 异常不扩展为恢复任务

发现文件或目录消失、服务异常、配置失效、归档不可恢复时：

1. 暂停该对象及其依赖的进一步清理，保全原始盘点、实际操作记录和仍存材料；原因未查明时不归咎于任一工具或参与者。
2. 如实记录清理前后差异、实际工具错误、服务变化、数据保持情况和未验证范围；原始证据不替换，不为检查通过重新生成“操作前”记录。
3. 完成其他独立且已获授权的收口项。恢复、重建、升级或服务迁移超出原范围时，单列最小处理范围及影响，取得必要授权后处理，不创建新库或新环境冒充旧环境已完整保留。

操作造成异常时也须保留真实责任与修复记录，不能把新恢复目录替代成原工作树已正常回收的证明。恢复成功与原收口是否完成分别报告；工具不可用时，不反复移交、恢复或切换删除手段。

## 台账和授权

用户明确请求的项目级调用覆盖本仓已确认结束任务的正常收口；并不宣布所有任务已经结束。操作前简短说明仓库、已结束候选、受保护对象及预计去留，在已有授权内连续完成。项目 AGENTS、远端保护、工具权限及用户更窄限制仍优先；真实新增边界才请求必要确认，不让用户重复粘贴完整指令。

项目级台账用 `scope: all-task-branches` 核对本仓全部本地、远端引用，主线之外每个引用都要交代：已结束任务按结果记录；继续开发和长期引用按明确约定或政策记录 `retained/agreed`；未知或因阻碍保留用 `retained/blocked`。列入台账只是核对去向，不授权修改这些受保护引用。限定任务用 `scope: selected`。

工作目录及运行资料范围来自真实任务归属和处置计划，不因引用全量审计就复制、停止或删除其他任务的环境。未纳入清理的继续开发任务，明确说明其环境未变更及保护依据；范围内待回收或保留的目录仍按最终台账核对数据与服务去向。

最终按已结束任务的收口结果、继续开发/长期保护对象、待确认/受阻对象分别报告。仍有必要清理受阻时整体为部分完成；按约定保护继续开发任务不等于该任务完成，也不能说项目分支或目录已经全部清空。
