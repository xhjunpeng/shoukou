# 整目录与历史收口（仅明确请求时）

日常收口不要加载本页。仅删除整个工作树、项目级全部收口或历史清理才适用。先读 `default-behavior.md`、`cleanup-check.md` 和 `final-check.md`，资源及空间核验按 `runtime-cleanup.md`、`storage-cleanup.md`。沿用原有脚本、授权与应用保护；完整扫描不能被轻量 Git 状态代替。

下文“完整收口”均指这个明确扩展的范围，不包括日常任务交付。

## 一次完整收口

选择完整收口后，在已解析范围内先逐个收口已结束任务的候选，再处理目标 `main` 中明确属于这些任务的改动。两个阶段共享台账；项目级审计中的继续开发、长期保留和待确认对象只记录保护或阻碍，不纳入合并和删除。

| 阶段 | 处理内容 | 不处理的内容 |
| --- | --- | --- |
| 候选分支阶段 | 所选范围内已结束任务的提交、验证、PR/合并和已合并分支清理 | 范围外、继续开发、长期保留或任务状态不明的引用 |
| 主分支阶段 | 合并后的目标分支、直接在 `main` 完成的范围内 L1 改动，或明确归属这些任务的未提交改动 | 归属不明、混合未完成任务或无法验证用途的改动 |

主分支阶段先检查 `git status`、本次合并结果和目标分支是否已同步。若 `main` 干净，只记录“主分支无待收口内容”；若存在明确属于本任务的改动，按 L0–L3 分级、执行适用验证后再提交/推送。绝不删除、重写或“清空” `main`，也不把主分支的无关改动带入本次提交。

限定范围时，未点名的其他任务不进入清理；项目级调用时，全仓引用进入审计，但只有已确认结束的任务进入处置。本次切换新目标所替换的旧分支属于已知候选。明确要求当前任务继续开发时，执行已授权的阶段提交或合并并保留候选；项目级盘点发现的其他继续开发任务不因此获得阶段提交授权。没有适用完成和验证证据时仅报告缺口。`盘点所有分支`永远只审计和输出台账，不执行批量收口。

## 旧规则迁移

审计输出包含目标基线与每个候选的 `closeout-policy` 标记时，比较两者：

- 标记相同或项目未使用该标记：按当前规则继续。
- 候选标记较旧：先说明“规则需同步”。仅对干净、明确属于任务且未被其他 worktree 使用的候选，合入或变基到最新目标基线后再收口；保留已有 PR，不创建重复 PR。
- 候选有未提交改动、被其他 worktree 使用或同步会产生冲突：不强推、不丢弃、不自动改写历史；在台账中标为“规则同步阻塞”，并保留分支。

不要把 PR 模板当作分支保护或项目政策；符合当前 L1 条件的变更不应只为填写旧模板而创建 PR。

## 分级与动作

| 级别 | 条件 | 收口动作 |
| --- | --- | --- |
| L0 | 临时产物、缓存、未知文件、草稿 | 已确认属于本任务且可重建的临时产物按下文回收；未知文件和草稿保留并说明归属缺口，不提交、不删除。 |
| L1 | 非运行时参考图、已确认设计资产、纯文案 | 确认工作区干净且项目允许后，做范围与敏感信息检查，提交并推送；无需 PR 或远程 CI。 |
| L2 | 代码、配置、运行时文档、UI 行为、测试 | 做相关本地检查；按项目/远端规则推送、创建或完成 PR；合并后验证目标分支。 |
| L3 | 权限、迁移、密钥、安全、公开接口、CI/发布、生产数据 | 执行项目规定的设计、独立验证、回滚和严格合并门禁；缺一项就只报告阻塞。 |

文件数量不是分级依据。存在未提交的无关变更、活动 worktree、未合并分支、目标分支不明或验证证据不足时，仅阻塞该候选，不影响其他合格候选。

## 运行资料与磁盘清理

完整收口包含本任务临时数据和一次性验收服务的去向处理；只要求提交、合并或盘点时不扩大为删除授权。按 [运行资料分类与复查](runtime-cleanup.md) 分类，并在最终台账填入 `runtime`。修改或验证本技能不授权清理其他项目的数据。

完整收口还须执行 [所选范围的完整空间复查](storage-cleanup.md)，默认仅当前任务，项目级与历史范围须明确要求：核实后回收已结束的测试环境、数据库快照、旧候选副本、验收专用依赖和构建缓存；历史日志、截图、备份与收口材料保留最小充分集合，逐组说明仍需保留的实际用途。不能仅列占用就结束，也不默认复制整套环境作为清理备份。目录受保护时，继续分别处理其中满足条件的独立临时批次。

- 分别核对聊天、目录、数据和服务。工作目录需要保留时，仍处理其中已确认不再使用的本任务临时产物；目录不能移交只阻塞目录清理，不自动阻塞已满足条件的数据回收。
- 对可从锁文件、迁移和已确认测试材料重建的数据，核实准确路径、任务归属、重建依据及无使用者后，在完整收口授权内清理。只清理已列明的文件或目录；忽略规则、目录名称、时间久或没有进程均不能单独证明可删除。
- 必要验收证据保留最小充分材料；真实业务数据、外部导入原件、凭据及归属不明内容分别保留。临时数据保留须写原因、依据和下次复核事件；用途未明记为阻碍，不改写成用户同意永久保留。
- 一次性验收服务按项目已有退出入口结束，只操作本任务确认拥有的服务；原有业务服务按确认范围保留。进程已停不等于数据已清理；数据已移走不等于服务已退出。
- 先核对日常服务、预览、定时启动及重启配置的实际依赖，保护所需源码、依赖、配置、凭据及数据库；位于 `.runtime` 或任务工作树不改变其用途。发现目录缺失、服务异常或附件失配时，按默认保护边界保全现场并暂停相关清理，不为完成收口自动重建、升级或迁移日常环境。
- 必须保留的在线服务正常追加日志、重建 JSON 缓存时，按 [在线保留文件的变化](storage-cleanup.md#在线保留文件的变化) 核实准确文件、真实写入者及来源，采用区间观察，不仅为通过核验要求停服或另做一致性快照。目录级豁免、数据库、配置、业务材料及验收原件不适用；该观察不证明内容原样保全，也不授予删除或迁移许可。
- 操作后复查数据、服务及空间。最终检查缺少运行资料记录、发现漏项或仍有阻碍时，不报告完整收口；已符合约定的保留逐项说明。目标目录占用减少、资料迁移量与磁盘可用空间变化分别报告，不把移动备份或移入回收站的体积算作已释放空间。

## 提交信息

提交前核对暂存内容只包含当前候选的一件完整变更；实现与对应测试可以同一提交，但不要混入无关格式化、重构或其他任务文件。

标题固定为 `类型(范围): 中文说明具体做了什么`。类型使用：`功能`、`修复`、`文档`、`测试`、`重构`、`配置`、`安全`、`维护`；范围写受影响模块、目录或任务。中文说明必须准确对应实际 diff；专有名词、命令和文件路径可保留原文。

示例：

```text
功能(客户管理): 新增客户列表状态筛选
修复(订单): 修正折扣金额精度计算
文档(FDE): 补充租户隔离决策说明
维护(收口): 清理已合并的 UI 基线分支
```

不得使用 `更新代码`、`修改内容`、`修复问题`、`fix bug`、`update` 等无法从标题判断实际变更的描述。涉及行为影响、迁移、风险或验证边界时，在正文用中文列出实际影响与已执行检查；没有额外信息时不需要凑正文。

## CI 与批量收口

GitHub Actions 已关闭、额度耗尽或检查未启动时，不重跑、不建议付费，也不把“未运行”表述成“测试失败”。仅当项目规则或真实分支保护把远程检查作为门禁时，记录该候选被阻塞。

按候选顺序串行执行：验证 → 推送/PR/合并（如适用）→ 检查目标分支 → 按本次方式保留候选或处理清理。删除目录前必须确认会话去向；独立清理未占用的旧分支不以目录移交为前提。Git 提交祖先关系或目标分支上的已合并 PR 可证明已合并，后者覆盖 squash 或 rebase 合并。使用 PR 证据时核对其目标分支与合并时的头提交，确保覆盖本次待清理的分支头；同名分支在合并后新增的返修提交不能沿用旧 PR 的合并证明。

### 旧分支独立清理

分支是提交引用，工作树是目录，会话关联的是目录；三者分别核验。“保留目录和预览”只约束目录及运行环境，旧分支是否保留按授权、合并情况和实际依赖单独判断。记录区分用户明确要求、规则要求与执行判断，不能把 AI 自行增加的保留对象写成用户要求。

仅清理已解析范围内确认结束且获清理授权的任务分支，或切换新目标时明确替换的旧分支；项目级盘点不解除其他引用的保护。删除前读取最新 `git worktree list --porcelain`、本地与远端分支头，确认成果已进入目标主线，且没有其他任务或未完成 PR 依赖待删除引用继续开发。远端分支须单独核验，不能以本地已合并推定远端新增提交也已合并；状态不明则保留并报告。

本地与远端引用分别判断：本地分支仍被工作树检出时，按下述完整收口例外核验；不符合例外则保留本地引用；这不会自动阻塞远端引用清理。远端头已合并、无继续推送/开发依赖且已有清理授权时，可单独删除远端引用，保留目录、本地分支和服务。远端删除使用准确引用及已核验头的条件删除（例如 `git push --force-with-lease=refs/heads/<分支>:<已核验头> origin :refs/heads/<分支>`）；此处仅允许比较旧头后删除，不能用于改写提交。头变化时保留并重查。删除后查询真实远端；再以 `git fetch origin --prune` 更新本地远端跟踪记录，不能把清除过期跟踪记录说成删除本地分支。

满足各自条件后可独立删除对应引用，无需移除原目录或移交仍在该目录工作的会话。只删除分支不会改变会话位置，也不会自动切回 `main`。本地分支承载返修或不符合下述例外时，先保留；阶段合并不为清理而强制切分支、分离 HEAD 或迁移会话。

切换新目标的交接记录必须写明被替换旧分支的核验结果：已清理，或因具体依赖、证据不足、缺少清理授权而保留。仅以“目录或预览需保留”不能结束旧分支核验；若待核验，明确报告该项未完成。

### 已结束任务的分支独立清理

完整收口已授权时，目录删除受阻不自动阻塞分支清理。仅对已确认归属本次已结束任务的工作树，核对准确分支头已进入目标主线、当前任务已结束、无其他写入者及服务/任务依赖继续使用分支引用；任何一项未知则保留分支。应用附件和原任务记录用于确认归属，最近聊天列表仅提供补充证据，不作为完整占用证明。

源码干净且满足上述条件、没有继续开发约定时，可分离到原 HEAD 后删除旧分支；源码不干净时，先按 [旧目录重复内容的处理路径](branch-cleanup.md#旧目录仍有未提交状态) 逐文件核实。全局单窗口例外适用时，两者都由当前统筹聊天直接执行 `scripts/branch_cleanup.py` 的前后检查：只有 `passed` 后才在准确目录分离到原 HEAD、复查源码和索引未变并删除引用，随后必须取得 `preserved`。仅未暂存及未跟踪的重复文件、准确同路径版本均已交付且进入主线历史时可走此路径；源码干净时文件版本表填空。独有改动走正常验收交付，受跨目录开发边界限制时保留并说明具体所需操作；暂存区修改、归属或用途未知仍保护，不能用快照或“历史里有同样字节”代替任务验收。

记录解关联前后的分支与提交；这两条路径均只处理分支引用，保留目录和提交，不移交或归档聊天，完整聊天占用核验仍是删除目录的前置条件。阶段合并、其他任务的目录、归属不明或活动依赖不使用例外。结束前逐项处理剩余分支并对照原始清单复查新增分支，不反复以同一“未提交”标记结束调查；确实受阻时给出已核查事实、准确缺口和下一步处理条件，不靠强删凑零。

工具只能提供有限聊天列表或无归档入口时，完成可独立处理的引用和提交，目录记为 `blocked` 并报告缺少的应用能力。不要反复要求用户确认同一清理，也不要把阻碍标成用户要求保留。创建新工作树前先检查可复用的已关联目录，并记录预计移交/归档入口；缺少清理能力不要求冒险复用或放弃必要隔离。

### 会话去向与工作树清理

合并证明代码已保留，不证明会话可以失去目录。删除工作树前核对已知关联会话，包括空闲会话，并确认继续使用会话的实际目录存在。进程停止、Git 干净或资料备份不能代替应用保护。应用核验有两条路径：完整关联查询，或下述受保护的原生归档。近期聊天列表保持“不完整”，不能据此宣称目录无人使用；已知聊天仍在目标目录时，两条路径都阻塞。未找到原聊天时，结合已知任务标识、附件、交接记录及原聊天查询继续定位。只读本机记录可以帮助定位，不能代替受支持应用接口的关联确认，也不能修改内部数据库。

原生归档路径仅适用于当前可用的 `mcp__codex_app__archive_worktree`：其接口契约明确拒绝主目录、固定或共享工作树，并保存可恢复 Git 快照。此动作须由持有附件且符合接口权限的聊天执行；当前窗口无此入口且无跨聊天消息授权时保留该目录，不因此停止独立分支和临时批次处理。用户另行明确授权协作时，先按 [单窗口规则](default-behavior.md#单窗口统筹与必要协作) 判断必要性，原聊天只执行具体回收动作，不重做项目收口。用新鲜 `list_artifacts` 原始结果绑定准确 identityKey 与目标路径，用 `read_thread` 核对原聊天已在另一个存在的目录。记录本次实际工具契约来源、已知关联聊天与进程结果。查询不完整不改写为完整，由这个接口执行本次共享保护。它不保护运行服务或未另行保全的忽略文件，因此 Git、验收、进程和逐文件备份检查仍全部执行。没有该保护契约、附件不明、已知聊天仍使用目标或接口拒绝时保留；不借此改用 shell 删除、其他工具或归档聊天。

删除前必须运行统一的只读检查 `scripts/inspect-repo.sh --base <准确目标引用> --check-cleanup <工作树绝对路径> --evidence <目录外证据JSON>`。退出码为 0 且 `cleanup_preflight=passed` 表示完整查询路径通过；`native-archive-ready` 只允许原聊天调用输出的 `required_native_action` 指定接口与准确附件，不是通用删除许可。两者都不代表删除完成。准备证据、适用边界和反例验证见 [清理证据与检查](cleanup-check.md)。失败或未知时只保留受影响对象，不影响其他可交付候选。

检查和实际删除不是原子操作。检查后不能继续写入、生成验证产物或沿用旧的通过结果；出现新写入者或状态变化必须重查。优先使用应用内置工作树归档并保留可恢复快照；原生入口失败不自动改用 `--force`、直接删除文件夹、`git clean` 或 `reset --hard`。这些操作不能用来让检查变绿；未提交成果需按原任务范围提交或保留在原目录，资料备份也不能自动授权丢弃源码。

脚本只验证 Git 现场和调用者提供的占用/附件证据，不能认证聊天查询完整性或模拟原生接口的共享保护，也不能控制应用自己的自动回收。代理核对原始查询及当前接口契约；调用后记录真实接口结果、可恢复快照、目录与 Git 注册状态、继续使用聊天的目录，再判断清理是否完成。原生接口拒绝或结果不明时保留并报告，不更换删除手段。本机自动回收、归档和内置移交按应用机制另行验证。

| 场景 | 收口动作与完成证据 |
| --- | --- |
| 完整收口，本地目录开发 | 保留原项目目录；确认无其他任务改动或写入冲突后，切到已同步的目标主线，再删除已合并任务分支。会话目录保持存在。 |
| 完整收口，仅保留已结束任务的聊天历史 | 不恢复旧任务的整套环境，也不为收口重建目录。回收前仍通过受支持方式核对和处理应用关联；无法安全回收时保留原目录并报告阻碍，继续独立处理分支和无用数据。 |
| 完整收口，工作树开发且明确继续使用该聊天开发 | 在不影响其他任务和日常服务的前提下，尝试通过受支持的内置移交回到可用目录，遵守用户明确保留工作树的要求。移交成功后重新读取会话实际目录、目标分支及文件状态，确认可用，再清理旧工作树。不能只依据工具已受理或聊天中说“已切换”。 |
| 移交不可用、失败或目标有冲突 | 保留原会话关联的工作树，报告“已合并，移交和清理未完成”及具体操作。不能绕过工具限制改任务内部数据库、在别的目录执行命令冒充移交，或先删目录等以后恢复。当前任务不能移动自身时同样适用。 |
| 用户明确授权归档会话 | 先保全成果及必要运行资料，按授权归档任务；确认没有其他仍需使用该目录的会话和进程后再清理。单独说“收口”不授权归档或删除聊天历史。应用已自动移除工作树时仅核验，不重复删除。 |

已归档会话仍留有工作树时，先核对应用记录的会话关联、工作树附件标识和可用内置归档入口，不默认恢复原会话。仅当已确认具体内置操作必须由原会话执行时，才在授权范围内恢复；恢复后先核对附件标识。标识缺失或登记不一致时，停止该归档路径，不反复恢复或移交，也不手工删除目录；保留对象并记录实际工具结果。能核实应用内修复入口就给出具体操作，核实不到则明确报告需要应用侧修复；修复后再归档并复查会话和目录状态。

移交改变的是会话与目录的关联，不保证目标自动处于 `main`；以真实 Git 状态为准。不得为切到主线覆盖其他任务改动。清理前相关预览、数据库和持久配置分别核对归属与授权；只阻塞受影响的清理步骤，不因此丢弃资料或默认永久保留全部工作树。

需要同时移除工作树及其当前分支时，满足上述会话条件后，再确认工作树专属、成果已合并且无待保留内容，先移除工作树，再按旧分支清理条件删除对应本地与远端引用。完整收口符合“已结束任务的分支独立清理”例外时，可先解除分支检出并删引用，目录仍按占用门禁保留；其余场景沿用上述顺序。必要截图和本地资料先在授权范围内归档并验证；资料未保全、归属不明或合并证据不足时保留。不要强推、删除未合并成果或修改其他任务的工作树。

结束前复查仍需继续开发的相关会话有存在且正确的目录；仅保留历史的聊天按已验证的应用关联结果报告，不把“历史保留”写成“开发环境已就绪”。台账分别报告提交、合并、会话位置、分支、工作树及运行资料去留。完整收口的每个遗留本地、远端引用均按 [遗留分支逐项取证](branch-cleanup.md#遗留分支逐项取证) 填写版本、任务、成果、分支依赖和阻碍处理记录，不能只用一句保留原因结束核查。阶段合并明确“本批已合并，任务继续”；项目级完整收口列出已收口、受保护及待确认任务，不宣称所有任务均已结束。继续开发聊天失去正确目录或必要清理受阻时报告未完成，保全证据；恢复或迁移超出授权时单列范围，不以新的恢复工作掩盖原清理结果。

## 完成判定与最终复查

Git 操作成功后，按 [最终复查与台账](final-check.md) 运行 `scripts/verify_closeout.py`，用最新远端引用、真实本地主线、分支和目录状态核对台账。完整收口还须通过 `scripts/storage_audit.py verify` 的所选目录与外置材料复查（任务级为 `selected-worktree`，项目级为 `full-project`，不得混报）；前一个检查单独通过不证明历史残留已处理。两者都不替代验收、清理前检查、资料备份或应用占用查询。

先读取两项检查的 `execution`，按 [未完成工作与真实阻碍](final-check.md#未完成工作与真实阻碍) 处理：`continue` 或退出码 3 表示还有核查或处理未做完，在原授权内继续，不用“部分完成”或“回复 1 继续”结束同一事项；`blocked` 须逐项核对原始停点证据后才可报告受阻。只有都无待办且原完成条件满足，才结束本轮完整收口。用户要求停止、必要授权未获准或真实环境阻碍另按实际边界处理，保全现场，不强删或绕过安全审查。

- 完整收口：验收、提交、合并/推送、本地主线同步、已授权清理、运行资料及服务去向和应用关联复查均完成，才报告“完整收口完成”。用户明确要求的保留可作为完成结果；因阻碍而保留仍是部分完成。
- 阶段合并：报告“本批已合并，任务继续”，列出按约定保留的分支和目录；复查通过不等于整体任务结束。
- 清理部分完成：开头直接说明已清理数量及剩余对象。对每个剩余对象写明实际阻碍、下一项具体操作及执行位置；工具只受理、目录未删或本地分支仍在时按实际状态报告。

## 最终回复：直接在聊天中展示

实际收口结束时，无论完整、阶段或部分完成，直接在聊天中给出结论和容量对比。默认不创建或导出收口报告、结果 JSON 副本、CSV/Excel、PDF 或压缩包，也不以报告文档或下载链接代替聊天正文；只有用户另外明确要求导出时才生成。检查脚本必需的机器输入和原始证据按 [控制本轮新增材料](storage-cleanup.md#控制本轮新增材料) 处理。

项目级结果由统筹聊天统一展示。受委派的单一查询或原生操作按 [必要协作规则](default-behavior.md#单窗口统筹与必要协作) 仅报告该动作的真实结果，由统筹聊天纳入总表；不因此另做一次项目收口或重复测量全项目。

使用以下列名；单项目也列一行，多项目逐个列出，并给出合计：

| 项目 | 清理前 MB | 清理后 MB | 目录占用减少 MB | 本地结果 |
| --- | ---: | ---: | ---: | --- |
| 当前项目／本次任务范围 | 实测值 | 实测值 | 前减后 | 实际删除、保留或受阻情况 |
| 合计 | 实测合计 | 实测合计 | 差值合计 | 实际整体结果 |

- 首次清理前采集容量，结束后按相同范围和口径复测；简要说明包含的主目录、工作树及已确认外置材料，重叠目录去重。表格采用分配空间，MB = 1,000,000 字节，保留两位小数；合计先按原始字节求和再换算。未发生清理也须按实际观测填写；未测、漏扫或缺少操作前记录时写“未测”及原因，不倒推、不填 0，不将不完整合计写成完整总量。
- “目录占用减少”按清理前减清理后计算；增长时保留负值。已核实不存在的目录才记 0，空目录保留、原目录本来不存在和本次删除须在“本地结果”中区分。
- 表格外另列合计变化、同一磁盘清理前后的可用空间及净变化；不同磁盘分别列出。目录减少、资料迁移和磁盘可用空间净增分别表述，不把备份、回收站或外置量算成实际释放量，无法测量或归因时如实说明。
- 紧接表格简要交代成果交付、分支、工作树、聊天目录、数据和服务的实际去留，以及必要保留、未完成对象及原因。容量降至 0 不代表所有收口事项完成，整体结论仍按上述完成判定。

历史清理不会自动授权重新开发未提交功能、迁移仍在使用的业务服务、归档聊天、给其他聊天发消息或发布本技能。发现这些边界时保留相关对象，完成其他已授权项；需要用户操作时说明准确聊天/目录和内置入口。查询不到入口就如实说明应用侧限制，不编造按钮或用手工删除替代。
