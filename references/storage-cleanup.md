# 全目录空间与历史材料收口

仅整目录删除或明确的全范围历史/项目清理执行本页；日常任务收口不加载、不执行本页。扩展范围内只读盘点可以运行采集，但不因此删除数据。目标是让范围内每份开发、测试和收口材料都有实际去向，不以“已处理分支”或“已列出占用”代替回收。

## 范围与测量

先按实际授权确定范围。日常收口只定位当前任务目录、公共 Git 管理目录及已确认的本任务外置材料，capture 传入 `--worktree <当前任务目录>`；只有明确项目级或历史清理才沿应用关联、仓库来源和任务记录定位主目录、全部注册工作树、旧副本、验收环境、外置备份及历史收口目录。名称和截图仅供定位，不据此纳入另一仓库。列出范围来源及使用者，保护继续开发、共享环境和日常服务；不要扫描整个用户目录或清理共享包缓存。

在成果交付后、实际资料清理前运行只读全量盘点，`--extra-root` 可重复传入已经确认的外置路径。早期已有盘点保留为原始记录；正式清理前记录不能覆盖它或掩盖已经发生的变化。为本轮确有必要生成的材料预先指定一个精简目录，也列为 extra-root；它可以尚不存在。盘点文件保存到所有测量根目录之外，优先 `.json.gz`，不输出巨量明细到聊天。

```bash
python3 scripts/storage_audit.py capture --repo /absolute/project \
  --extra-root /absolute/project-closeout-records \
  --extra-root /absolute/confirmed-old-copy \
  --output /absolute/outside-reviewed-roots/storage-before.json.gz
```

上例为项目级完整范围。日常任务在 capture 命令中增加 `--worktree <准确任务目录>`，结果为 `kind: selected-worktree-storage`；review 增加 `scope: selected` 和同一路径的 `worktree`。verify 输出 `measurement_scope: selected-worktree`，不能据此宣称所有历史工作树已处理。详见 [台账与任务范围](artifact-ledger.md)。

它统计所选根目录的所有条目，包括非忽略文件、嵌套仓库及 Git 元数据；包含公共 Git 目录，重叠根目录只计一次，分配块按硬链接跨根去重，不跟随符号链接。挂载点、读取失败或变化导致的漏扫明确列为缺口，不能声称完整盘点。符号链接指向的实际占用，如属本项目另以准确 extra-root 纳入；不自动跨项目跟随。

按完整目录总量、主要类别、单个保留组报告容量；单独列运行必需文件和数据、维护源码、开发/验收残留、外置材料、Git 元数据。不要用安装包大小推定项目大小，也不要以忽略文件合计冒充完整目录。Git 历史须计量和解释，不手工删对象、改写历史或执行激进压缩来凑空间目标。

## 默认处理开发与验收残留

按体积从大到小核对，但覆盖全部已确认范围，不以“最大的几项已删”作为完成标准。逐组核实实际用途、是否有唯一内容、替代材料和使用依赖后执行：

| 内容 | 完整收口的默认去向 |
| --- | --- |
| 隔离数据库、集群、快照、临时素材与恢复副本 | 验收结束且无使用者时清理；保留真实数据、唯一原件和仍需的故障现场 |
| 各轮候选副本、嵌套平台源码、验收专用依赖、构建结果、旧测试安装包 | 成果已进入准确主线或已有可验证来源、没有唯一改动且没有运行/维护依赖时清理；独立仓库和未提交成果先按相应保护处理，不因“副本”绕过保全 |
| 截图、测试输出、重复日志、各批报告 | 保留准确最终版本的最小充分验收集；跨尺寸、语言和主题中仍支撑结论的独有证据保留，不按数量随意截断。已被替代的中间产物在核实覆盖关系后清理 |
| 历次收口清单、同步记录、旧备份与多轮审计材料 | 保留必要交付索引、准确版本、最终验收、关键异常及本轮去留记录；已有可靠交付来源且无独有内容的重复备份和旧完整盘点按覆盖关系清理，未解决问题的证据保护 |
| 日常应用、原数据库、配置、签名与凭据、用户输入和原始附件 | 按实际用途保护；签名资料不是普通构建缓存。日常服务依赖任务目录时记录具体阻碍，继续独立清理其他批次；迁移另按授权处理 |

“以后可能用”“这是证据/备份”“聊天还在”不足以永久保留整批环境。每个保留的测试或历史材料组都要写明**当前用途、所支撑的版本/结论、使用者或约定来源、容量和复核事件**。无真实保留依据就核实并清理；仍无法核实记受阻，不擅删也不假装精简完成。不可用“最终报告”代替仍有必要的原始材料。

## 控制本轮新增材料

优先复用可信的提交、交付包及必要索引；仅为清理生成所需清单、摘要和最小证据，不默认复制整个工作树、数据库、依赖和全部截图。应用归档接口必需的恢复快照仍按契约保留并计量，不手工删除内部快照；发生大幅增长时解释原因。

最终结果按 [聊天输出格式](../SKILL.md#最终回复直接在聊天中展示) 直接展示，默认不另存报告或下载表格。检查必需的盘点、review、ledger 和应用查询原始结果只生成最小核验集合，集中放在测量和清理范围之外；保留到全部相关复查结束，不能为减少文件跳过检查或提前删除输入。结论已记录到聊天后，清理本轮生成、已无后续用途且可重建的临时输入和重复输出；未解决异常的原始证据、唯一材料、明确要求保留的记录和应用要求的恢复快照继续保护，并在聊天中说明保留原因、容量及复核事件。

确需外置保全的唯一材料按原资料检查逐文件核验；有用的备份不因去重目标被删除。外置、压缩和移入回收站都不等于释放空间。本轮新增的外置材料及已有备份纳入前后统计，避免在主目录减掉一份、又在另处复制一份却宣称已释放。范围之外的清单文件也单列实际大小；它不纳入目录测量以免清单不断把自身写大。

## 在线保留文件的变化

日常服务须继续运行时，先区分正常日志追加、可重建缓存更新与异常资料变化。仅因这些正常更新，不要求停止服务、迁移资料或建立一致性快照；需要内容保全、数据库备份或迁移时仍执行对应授权与一致性检查。

检查器只对准确单文件接受 `dynamic` 声明，且动作必须为 `retained`，保留依据仍须符合原有分类规则。仅支持 `kind: runtime` 配合 `role: append-log` 的 `.log` 文件，以及 `kind: cache` 配合 `role: replace-cache` 的可重建 `.json` 文件。不得用于源码、配置、凭据、数据库、业务数据、验收原件或来源不明的文件；不得把这些内容改标为日志或缓存来通过。Git 跟踪文件及 `.git` 路径拒绝。

执行者先读取已有进程、启动配置和文件用途记录，核实进程确为该文件的实际写入者。仅 PID 存在、文件名相似或端口一致不足以证明归属。来源证据使用已有非空普通文件原件及其 SHA-256，不以新写一份自述代替原始记录；检查器只核对文件与摘要，不认证记录内容或进程是否真正拥有文件。

下例作为准确相对文件名规则的值；父目录及其他成员另行分类，不与目录前缀规则重叠：

```json
{
  "kind": "runtime", "action": "retained", "retention": "required",
  "reason": "原有日常服务继续运行", "source": "已核实的启动配置及文件使用记录位置",
  "dynamic": {
    "path": "/absolute/runtime/daily/logs/service.stdout.log",
    "role": "append-log", "pid": 12345,
    "owner_signature": "进程启动时间与命令输出的SHA256",
    "observed_at_unix": 0,
    "source": {"path": "/absolute/existing-owner-evidence.txt", "sha256": "原始归属记录的SHA256"}
  }
}
```

在核验开始前取得新鲜观察。`observed_at_unix` 是该观察的 Unix 秒数，须在核验开始前 120 秒内，最多允许未来 5 秒误差；长扫描以开始时间判断新鲜度。`owner_signature` 是 `ps -p PID -o lstart= -o command=` 的标准输出原始字节去掉首尾空白后的 SHA-256，可用 Python 的 `subprocess.check_output(...).strip()` 和 `hashlib.sha256(...)` 计算。它绑定 PID 对应的启动时间与命令，避免同一 PID 被复用；不把完整命令或可能的凭据打印到聊天。核验初次及结束复查均实时核对进程签名与来源摘要。

日志须仍为同权限的普通文件，大小不能缩小，同大小却修改时间变化也拒绝；全目录盘点还核对设备与 inode，拒绝日志替换。缓存须有明确 `rebuild`，当前文件须为有效 JSON；缓存可在同路径原子替换。全目录复查只允许此类准确文件导致的祖先目录元数据变化，目录身份及权限须不变；其他新增、消失、链接替换、未声明变化或读取失败仍拒绝。不要用全目录 `dynamic`、宽泛可变开关或重做操作前盘点掩盖异常。

`dynamic_observations` 记录准确路径、角色、PID、观察时间和前后字节数。它接受有来源支持的元数据变化，不证明日志旧内容逐字节未改，也不证明 JSON 缓存的业务正确性。容量是扫描期间观察值，不是同一时刻的静态快照；仍分别报告目录差值与磁盘可用空间变化。声明不足时继续核实，不能将正常更新自动列成要求停服的外部阻碍。

## 全量去向复查

分类未完成时，检查器给出 `status: incomplete`、`execution.unfinished` 和退出码 3；继续完成准确目录或材料组的分类，不能将这一状态解释为应用或权限阻碍。真实无法继续时按 [逐对象停点证据](final-check.md#未完成工作与真实阻碍) 填写 `stops`；已分类但用途仍未知、需要保留的组也适用同一执行判断。补齐输入不授权删除未知内容。

在外部保存以下 review JSON。`classifications` 必须覆盖 capture 的每个根目录；每个条目只匹配一个准确相对名或以 `/` 结尾的目录前缀。不接受整根兜底规则；不同用途的子树拆开，不能把整仓都标成必要源码或证据。Git 元数据通常以 `.git/` 单独保留，共用 Git 目录是独立根时按其实际顶层内容分组。

```json
{
  "before_inventory": "/absolute/outside-reviewed-roots/storage-before.json.gz",
  "before_sha256": "采集时返回的完整文件摘要",
  "classifications": {
    "/absolute/project": {
      ".git/": {"kind":"git-metadata","action":"retained","retention":"required","reason":"维护所需版本记录","source":"准确仓库及项目约定"},
      "src/": {"kind":"source","action":"retained","retention":"required","reason":"维护源码","source":"已交付版本和当前任务记录"},
      "test-environments/": {"kind":"test-data","action":"removed","reason":"验收已结束，无唯一业务数据或使用依赖","source":"准确批次和依赖核查","disposal_basis":"迁移、固定测试材料和准确版本可重建"},
      "old-reports/": {"kind":"evidence","action":"superseded","reason":"中间报告已被最终验收集覆盖","source":"逐批证据覆盖核对","replacement":"/absolute/project-closeout-records/final.json","sha256":"替代材料的SHA256","coverage":"准确版本、最终结果和必要原始证据索引均已保留"}
    },
    "/absolute/project-closeout-records": {
      "final.json": {"kind":"evidence","action":"retained","retention":"required","reason":"本次最终交付记录","source":"本次收口结果","need":"支撑准确最终候选的验收与去留","review":"被下一份覆盖同等事实的记录替代时复核"}
    }
  }
}
```

上例不是可直接套用的完整目录表；实际配置、锁文件等每项均要纳入。其他分类有 `runtime`、`business-data`、`unknown`、`cache`、`build`、`copy`、`backup`、`audit`。`git-metadata` 仅适用于本项目真实公共 Git 目录及工作树管理路径，允许正常收口改变引用成员，不能用于给普通源码副本免检。

- `removed` 只允许临时类别（cache/test-data/build/copy/backup/audit），须提供 `disposal_basis`，且条目确实不存在。来源/唯一改动检查由真实证据支持。
- `git-admin-retired` 仅用于选定工作树被安全移除后，Git 自动退役的准确公共管理目录 `<git_common_dir>/worktrees/`，类别必须为 `git-metadata`。检查器要求原始登记恰为主目录与所选工作树、当前只余同一主目录、所选目录及该管理组已不存在；缺少原始登记证据拒绝。它不是删除许可，也不能用于源码、业务数据、其他 Git 目录或仍有工作树登记的情况。不要把已退役组谎写为仍然 retained。
- `superseded` 用于已被替代的 evidence/audit/backup/copy，须有保留下来的普通文件、摘要、覆盖关系；替代材料必须在测量范围内，自身另列保留。不能删业务材料再以一份摘要报告声称已替代。
- `retained` 须有来源、原因和 `retention`（agreed/required/blocked）；临时类别、evidence 和 unknown 还须有 `need`、`review`。未知或受阻对象导致部分完成；维护源码及必要运行/业务/证据组的原成员丢失或类型改变会拒绝。清理期间这些材料的文件元数据改变须复核；源码变化须结合准确 Git 交付及验收证据核对，不能重新盘点来掩盖意外丢失。

```bash
python3 scripts/storage_audit.py verify --repo /absolute/project \
  --review /absolute/outside-reviewed-roots/storage-review.json
```

退出码 0、status complete 仅表示这份完整空间台账与文件现状一致。partial 为缺口，blocked 为矛盾；输入或读取错误为退出码 2。未分类条目、漏项、新增工作树、扫描失败和声称已删但仍存在的内容不能作为完整结果。检查只读，不认证分类、使用者、替代覆盖或删除授权。

完整收口须同时通过本检查、原 `verify_closeout.py` 的 Git/运行资料检查及应用关联复查。原脚本单独输出 complete 不证明全目录或历史材料已收口。最终分别报告完整目录减少量、外置材料前后及本轮增长、必要保留及受阻组、磁盘可用空间变化；共享块、压缩及其他程序写入影响归因，不承诺释放固定 GiB。验证会复扫，但扫描与实际操作不是原子事务，现场变化时重查。
